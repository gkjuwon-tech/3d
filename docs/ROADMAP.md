# 로드맵 — 현재 마일스톤 이후

> 기록: 2026-09-23. 순서대로 진행. 각 단계는 앞 단계 품질이 숫자로 확인된 뒤 시작.

## 0. 현재 마일스톤 — GT 입력 재구성 품질 (진행 중)

루시 + 스탠포드 스캔 6종을 정답 렌더(14뷰, 12조명)로 재구성하고 품질 확인.

- 루시 현재: **F@1 97.1**, F@2 99.2, chamfer 0.000431, 메쉬 조각 1개 (닫힌 외곽면)
  - 8조명 92.4 → 12조명+탐색 160 94.7 → 엣지 바닥 95.7 → 잔조각 제거 96.7 → 외곽 셸 97.1
  - 얼굴 99.6, 손 99.4, 횃불 손 98.8, 발 95.6, 머리카락 98.3~99.6, 귀 밑 89.2
- 남은 오차의 정체 (13박스 융합 테스트 벤치로 확인): 융합 파라미터는 포화(어떤 조정도
  평균 ±0.5 이내). 남은 건 **카메라 한 대만 보는 곳** — 깊은 옷 주름 안, 팔과 몸 사이,
  날개 밑, 귀 밑 틈. 거기는 다른 뷰가 안 보니 스테레오 앵커가 불가능하고, 정답 깊이에서도
  매칭 비용이 임계값을 못 넘음(4~14%만 통과). 알고리즘이 아니라 카메라 배치 문제 → 2번.
- 완료 기준: 6개 모델 결과를 숫자와 근접 샷으로 확인 (12조명 촬영 진행 중)

## 1. 외곽만 남기고 내부 비우기 — ✅ 완료 (fuse_field `--shell`, stage2 기본)

융합 메쉬 안쪽에 꼬인 면·내부 공동·떠다니는 조각이 남을 수 있음. 외곽 껍데기만 남긴다.

- 방법: 점유 격자에서 바깥 경계부터 flood fill → 바깥에서 닿지 않는 영역은 전부
  속으로 채움 → marching cubes → 외곽 한 겹만. 내부 면은 구조적으로 생길 수 없음.
- ✅ 속 비우기 (3D 프린트용): `stage2.py --hollow T` → `recon/mesh_hollow.ply`.
  바깥 표면은 그대로, 벽 두께 T칸 보장(최소값), 두께 2T보다 얇은 부위는 꽉 채움,
  1000복셀 미만 빈 공간은 버림. 루시 T=8: 재료 37.1%, 벽 최소 8.00칸,
  열린 모서리 0, 비다양체 모서리 0, 바깥 F@1 97.74 그대로.
  (단면: `docs/img/lucy_hollow_section.png`)
- ✅ 면 방향 버그 수정: 모든 메쉬가 뒤집혀 있었음(부호 부피 음수). 렌더러는 양면이라
  안 보였지만 슬라이서에서는 문제. 이제 바깥 +, 빈 공간 쪽 −.
- 파이프라인 연결: `stage2.py` 마지막 메싱 단계 직후.
- 검증: 연결 성분 수 = 1, 자기교차 0, 내부 면 0, F@1 변화 없음.

## 2. 뷰는 18개 유지, 이미지 한 장에 3뷰씩 생성 → 6장 (2026-09-24 변경)

~~뷰 개수를 6~7개로 줄이기~~ → **폐기.** 부처 받침대 조사 결과 표면의 상당 부분이
카메라 두 대 이하에게만 보이고, 그런 곳은 둘이 같이 틀려도 바로잡을 표가 없음
(14뷰에서 받침대 윗면 60%, 루시 22%, 타이 32%). 오히려 커버리지 분석으로 위쪽
4대를 추가해 **18뷰**가 됨 (`render_orthoviews --aux upper4`). 뷰를 줄이는 방향은 불가.

**새 방향: 뷰 수는 그대로, 생성 호출 수를 줄인다.** 이미지 모델에게 한 장에 3개
시점을 나란히(3패널 시트) 그리게 해서 18뷰 = **6장**.

- 호출 수: 18뷰 × 12조명 = 216장 → 6장 × 12조명 = **72장** (3분의 1).
- 덤: 한 장 안의 패널끼리는 이미지 모델이 서로 일관되게 그리는 경향이 강함
  (멀티뷰 시트). 같은 시트에 묶을 3뷰는 서로 가까운 각도끼리 → 일관성 이득 최대.
- 조명: 광도 스테레오는 **카메라 기준** 조명 방향이 필요. 시트의 세 패널 모두
  "각 패널의 카메라 기준으로 같은 방향에서 조명"으로 지시 (예: 12개 조명 각각 = 시트 12장).
- 레이아웃: 패널 간 여백(거터)과 정렬 표식을 두어 자동으로 잘라낼 수 있게.
  잘라낸 뒤 각 패널은 기존 파이프라인의 한 뷰로 그대로 들어감.

**가장 큰 리스크 = 패널당 해상도.** 지금 파이프라인은 뷰당 2048². 3패널이면
생성 해상도에 따라 뷰당 ~680~1365 px. 먼저 이것부터 숫자로 잰다:

1. 실험 (GT로, 생성 없이): 루시 18뷰 렌더를 뷰당 1365 / 1024 / 683 px로 줄여서
   전체 파이프라인 → F@1 / F@2 / 영역별 점수가 해상도에 따라 얼마나 떨어지는지.
2. 결과에 따라: 필요한 생성 해상도 결정, 혹은 시트를 2뷰로(18뷰 = 9장) 타협.
3. 시트 프롬프트/레이아웃 설계는 4번(2D 일관성 엔진)과 같이 진행.

## 3. 속도 단축

- 현재: stage1 광도 렌더 (블렌더, 12조명 × 14뷰 ≈ 40분), stage2 (Kaggle GPU, 8분 +
  탐색 범위 확대로 증가 예정).
- 생성 경로에서는 stage1 렌더가 이미지 생성으로 대체되므로 stage2 + 생성 시간이 핵심.
- 먼저 단계별 시간을 측정하고, 가장 큰 것부터 줄인다.

## 4. 2D 일관성 엔진 구현

`docs/GEN_PLAN.md`(Plan A 프록시 제어 + Plan B 보정)와 `docs/DEAI_PLAN.md`를 구현.
생성 입력의 시험지를 GT 입력의 시험지와 같게 만드는 것이 목표.

- 프록시가 형태를 소유 → 카메라·실루엣이 구조적으로 정확
- 이미지 생성은 표면만 → ControlNet 등으로 프록시의 깊이/노멀/마스크를 조건으로
- 조명 변형 생성 → 광도 스테레오 (AI 없는 법선)
- **업데이트 (2026-09-23 실험 결과)**: DEAI_PLAN의 "조명 3개"는 부족. 그림자 때문에
  4개는 한 뷰의 17%, 8개는 틈의 30%가 법선 없음. 12개(바깥 8 + 시선축 근처 4)가 필요.
  생성 이미지 수 = 시트 수 × 12. 18뷰를 3뷰 시트 6장으로 묶으면 72장 (2번).
- 가장 큰 리스크: 생성된 조명 변형들이 물리적으로 일관적인가 (Lambertian, 그림자 방향).
  첫 실험: 루시 한 뷰를 정답 노멀로 조건 걸고 12조명 생성 → 광도 스테레오 →
  정답 대비 각도 오차. 렌더 조명 기준치 0.6~0.8° 중앙값과 비교.
- 발광(용암 틈 등)은 Lambertian 가정 위반 → 마스크 또는 조명 변형 시 발광 끄기.

## 5. Text-to-3D 검증

텍스트 → 프록시 → 일관성 엔진 → 재구성 → 메쉬, 끝까지.

- 보정: 루시를 생성 경로에 통과시켜 GT 대비 점수 손실 측정 (GEN_PLAN B5).
- 그 수치로 기준값(재생성 기준, 실루엣 팽창량, 카빙 예산) 결정.
- 최종: 정답 없는 크리처(`docs/PROMPT_PACK.md`의 Cinder Basilisk 등)로 실행.
